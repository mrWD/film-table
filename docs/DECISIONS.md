# Принятые решения

Почему сделано так, а не иначе. Полезно, чтобы не переигрывать заново то, что уже
обсуждали, и не наступать на грабли, с которых уже слезли.

## PWA вместо нативных приложений

Требование было: Android, iPhone и веб. PWA даёт все три из одной кодовой базы, без
магазинов, без ревью, с бесплатным хостингом статики. Цена — нет пуш-уведомлений на iOS и
установка через «Добавить на экран Домой». Путь к сторам при желании — Capacitor, тот же код.

## Никакого бэкенда для данных пользователя

Библиотека лежит в `localStorage`. Следствия, с которыми сознательно согласились:
нет синхронизации между устройствами (вместо неё ручной Export/Import), данные привязаны
к домену (поэтому переезд на другой домен требует переноса), и нельзя потерять чужие
данные, потому что их у нас нет. Последнее заодно снимает вопросы GDPR.

## Источники дополняют друг друга, а не заменяют

Идея владельца, и она оказалась правильной. Ни один источник не покрывает всё: у TVmaze
лучшие данные по эпизодам, но поиск ограничен десятью результатами; у Cinemeta полный
каталог с постерами, но нет гарантий доступности; у iTunes сломан фильтр фильмов; TMDB
хорош во всём, но требует ключа. Слияние с таймаутами даёт лучшее из каждого и переживает
отказ любого. Подробности и замеры — в DATA-SOURCES.

## Прокси к TMDB, а не ключ в клиенте

Ключ в клиентском бандле публичного репозитория — это ключ, опубликованный навсегда.
GitHub Pages серверный код хостить не умеет вообще, поэтому появился Vercel с
serverless-функцией. Прокси даёт и второй выигрыш: edge-кэш экономит квоту.

Важно понимать ограничение: прокси защищает **ключ**, но делает **доступ** публичным —
любой может дёргать наш эндпоинт. Отсюда allowlist путей, проверка Origin и кэш.
Это снижает злоупотребление, но не делает API приватным.

## Дизайн уведён от TV Time

Изначально интерфейс воспроизводился по скриншотам TV Time — так и было задумано. Перед
публичным постом решили развести: свои подписи секций (UP NEXT / NOT STARTED / BEEN A
WHILE / CAUGHT UP), формат эпизода `3×01` вместо их `S03 | E01`, фиолетовый акцент вместо
жёлтого, свои заголовки секций.

Причина: идея и функциональность не охраняются, но дословные подписи плюс узнаваемая
вёрстка вместе читаются как копия чужого trade dress, а публичный пост это подсвечивает.
После развода претензия практически теряет предмет. **Не возвращать элементы TV Time.**

Там же добавлены дисклеймер «not affiliated with TV Time or Whip Media» и MIT-лицензия —
последняя в первую очередь ради пункта «AS IS, без гарантий».

## Донаты

Ссылки (Buy Me a Coffee, Ko-fi, PayPal, аккаунт `ipupok`) взяты из соседнего проекта
владельца `~/Projects/double-subtitles`. **При изменении там нужно обновить и здесь**, в
`src/components/Support.tsx`.

Кнопка-веер стоит **слева** снизу, и это не эстетика. Замер: справа плавающая кнопка
накрывала чек-ин или «плюс» на **42% позиций прокрутки**, слева — на 0%, потому что
правая колонка занята главным действием приложения.

Открытый вопрос: ключ TMDB получен с сертификацией «generates no revenue», а в приложении
есть кнопка приёма чаевых. Формально это серая зона. Потолок риска — отзыв ключа TMDB
(приложение при этом не ломается, работает фолбэк). Альтернатива, которую предлагали и
которую владелец пока не выбрал: убрать кнопку из приложения, оставив ссылки в README и
в посте.

## Рекомендации — content-based

Коллаборативная фильтрация требует поведения других пользователей, то есть бэкенда,
который мы принципиально не заводим. Content-based на жанрах работает достаточно хорошо
для личного трекера. Детали алгоритма — в ARCHITECTURE.

## Статистика — только локальная

Скрытая страница `/insights` считает использование **этого устройства**. Настоящая
посещаемость сайта требует агрегации на сервере, а бэкенда для пользовательских данных у
проекта принципиально нет.

Посещаемость всеми пользователями закрыта **Vercel Web Analytics** (включено 2026-07-26,
тариф Hobby: 50 000 событий в месяц, история 30 дней). Без кук и персональных данных,
смотрится в дашборде Vercel. Альтернативой был свой счётчик в serverless-функции с
хранилищем — отвергнут: пришлось бы решать, что именно хранить о посетителях.

Внутри приложения агрегированные цифры показать нельзя без серверного токена, поэтому
`/insights` и дашборд Vercel — два разных экрана, а не один.

## Грабли, на которые уже наступали

- **Клики по карточкам.** Карточки — это `<Link>`, а кнопки внутри них требуют и
  `stopPropagation`, и `preventDefault`, иначе тап по «плюсу» уводит на страницу.
- **Вложенные `<button>`.** Заголовок сезона с чекбоксом внутри — невалидный HTML, React
  ругается в консоли. Разделено на соседние элементы.
- **Горизонтальный скролл.** У элементов CSS Grid по умолчанию `min-width: auto`, поэтому
  длинное название в постерной сетке распирало страницу на 206px. Лечится `min-width: 0`.
  Проверять переполнение **на ширине 375px** — на широком окне баг не виден.
- **`"type": "module"`.** Функция Vercel должна быть ESM (`export default`), CommonJS в
  этом репозитории не запускается.
- **Catch-all маршрут на Vercel.** `api/tmdb/[...path].js` сопоставлялся только с одним
  сегментом: `/api/tmdb/x` доходил до функции (отвечал 403), а `/api/tmdb/search/movie`
  отдавал 404 статикой. Лечится отказом от catch-all — путь передаётся параметром
  `?path=search/movie` к обычному файлу `api/tmdb.js`.
- **Порты в allowlist прокси.** Жёстко прописанные порты localhost ломают проверку при
  запуске dev-сервера на другом порту — разрешён любой loopback.
- **Одинаковые объяснения рекомендаций.** Если брать глобально самые весомые тайтлы,
  под всеми карточками появляется одна фраза. Считать пересечение для каждой карточки.
- **Побочные эффекты в редьюсерах zustand.** Счётчик, вызванный внутри `set((s) => ...)`,
  срабатывает дважды под StrictMode. Держать их снаружи, до или после `set`.
- **Аналитика и HashRouter.** Vercel Web Analytics шлёт событие только на полную загрузку
  страницы: смена хэша навигацией не считается, поэтому поэкранной воронки не будет.
  `beforeSend` всё же нужен — без него единственное событие приходит как `/` вместо
  реального экрана входа.
- **Service worker прячет свежий деплой.** После выката браузер продолжает отдавать старую
  сборку из precache. Проверять прод после деплоя — только после `unregister()` service
  worker и очистки `caches`, иначе легко принять кэш за неудавшийся деплой.
- **Скриншоты во время загрузки.** Постеры грузятся лениво; пустые плитки на снимке чаще
  означают «не успело догрузиться», чем поломку. Проверять `naturalWidth`, а не глазами.
